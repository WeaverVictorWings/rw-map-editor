# 2.4 开发任务书（交接用）

给接手的智能体：先读完本文再动手。项目是铁锈战争（Rusted Warfare）地图编辑器，安卓优先，同一套代码也跑在电脑浏览器里。当前版本 2.3，目标版本 2.4。

## 0. 项目约定（必须遵守）

- 代码：`www/js` 下的原生 ES 模块，没有构建步骤。安卓用 Capacitor 7 打包。发布由 GitHub Actions 完成：按 `package.json` 的版本号发布，版本号末尾的 ".0" 会去掉（2.4.0 → Release 名为 "2.4"）。包名和签名不变，APK 可以覆盖安装。
- 界面文字：源文字写中文，`www/js/i18n.js` 在 DOM 层按词典翻译成 11 种语言。**每新增或修改一句界面文字**，都要：
  1. 把它加入 `scripts/i18n/strings.txt`（格式：id、制表符、文件、制表符、JSON 字符串）。
  2. 给每种语言写译文：`scripts/i18n/<lang><n>.tsv`（id 制表符译文，`∅` 表示空）。
  3. 运行 `node scripts/i18n/build.mjs <lang>` 生成 `www/js/i18n/<lang>.js`。繁体中文由 `zht-opencc.py` 自动转换。
  4. 用户自己起的名字加 `translate="no"`，画布上的文字走 `window.__rwT`。
- 不要内置游戏素材。图块和单位图都从用户导入的地图里取。
- 测试要节省：用 `tests/` 里已有的脚本（`smoke.mjs`、`v22.mjs`、`v2m.mjs` 等），截图只在必要时才截。用法：`python3 -m http.server 8765 --directory www`，然后 `PW=<playwright路径> node tests/<name>.mjs <样例.tmx> <输出目录>`。测试浏览器要设 `locale: 'zh-CN'`。

## 1. 最高优先级：资源池必须是真正的 1×1

用户反馈（原话大意）：原版地图编辑器里资源池外观和占位都是 1×1，不是“看起来 1×1、实际占 3×3”。要让资源池能紧密排布，就只能是 1×1。

已查明的原因：2.1 只把放下去的那一格改成了 1 格，周围规则仍按 3×3 计算。

- `www/js/panels.js` 的“最小间距”滑块最小值是 1，默认 4；`www/js/paint.js` 的 `placeItems` 里 `spacing = Math.max(1, … ?? 4)`，并且 `near()` 在 spacing 为 1 时只排除同一格。结果是画资源池时彼此必须隔开 3 格，紧挨着放不上去。
- `www/js/check.js` 的“资源池和单位挨得太近”按上下左右各 2 格判断，是 3×3 的假设。
- 还要逐个核对是否有 3×3 假设：`stamps.js`（`pool()`）、`gen.js`（`placePoolsAround`）、`detail.js`（保护范围 `mark(x, y, 2)`）、`pathing.js`、`transform.js`（缩放时池的处理）、`terraform.js`、`extras.js`、`triggers.js`。

要求：
1. 资源池的“最小间距”默认 0（相邻也可以），滑块范围 0–30。1×1 样式下，间距为 0 时允许紧挨着放，也允许拖动画成一排。
2. 检查只在资源池正上下左右紧贴单位时才提醒；文案改成“紧贴”。
3. 印章、新建地图、随机生成、自动细节、缩放、镜像、对称检查里所有对资源池的间距、保护范围、边缘排除，在 1×1 样式下按 1 格算。
4. “3×3 带边框”保留为可选样式，但只有选了它才按 3×3 算；两种样式混在一张地图里时也要正确识别每个池的中心格（`ed.poolTiles()` 现在按带 `res_pool` 属性的图块识别，保持不变）。
5. 增加测试：连续放 5 个相邻资源池 → 图层里有 5 个 res_pool 图块；检查不报间距警告；缩放、镜像后数量不变。

## 4. 已知问题（别重复踩）

- 自动细节在平地上效果偏弱；河流宽度太均匀。
- 非中文、英文的界面只测过文字覆盖率，没有逐个功能走过；俄语、乌克兰语、土耳其语、日语里数字拼接的句子读起来偏生硬。
- 长篇帮助文字在 8 种非中英文语言里是英文。
- 需要在游戏里验证：色块的 ford、lava 属性；`.rwmod` 合集包能否被游戏识别；印尼语地图文字后缀是 `_id` 还是 `_in`。
- 2.3 的 GitHub Actions 构建结果没有在会话里核实（当时没有授权访问改名后的仓库）。
